05 · Progress

Three parts, or it isn't an indicator

4dp default track, configurable thickness, optional wavy shape. Every linear indicator here keeps the same anatomy.

active primary track secondary container stop 4dp, primary severity my call: tertiary / error

The 4dp track is the default. 8dp and wavy are Expressive configurations — the wavy shape needs canvas work in Glance, the flat ones don't.

If I had to pick three

  1. 04 — every window as a list. It is the only arrangement that fixes the “17% is wrong” feeling without new data: the number is the monthly meter, and the 5h limit is now visible next to it.
  2. 11 — verdict pills. “17%” plus “dry in 4d” is a decision. Pace.willLastToReset and etaSeconds are already cached.
  3. 02 — wavy indicator with a clock notch. A sanctioned M3 Expressive shape that removes the sausage look while keeping the at-a-glance bar.

Twelve of the twenty are pure role/typography changes to widget/WidgetContent.kt. The wavy indicator, the charts and the timeline need RemoteViews work (Glance has no canvas API), so treat those as the expensive ones.

Rules to apply regardless

  1. Never print a bare percentage: pair it with its window and the word “left”.
  2. Use the indicator’s three parts — active, secondary-container track, 4dp stop — or don’t draw one.
  3. One hero per widget. Everything else is a list row at title-small.
  4. Let dynamic color pick the accents; keep only primary / tertiary / error as semantic state.

Specs quoted here come from the M3 token set: corner scale 4/8/12/16/20/28/32/48/full, type 36/45/57 display, springs 0.8/380 spatial and 1.0/1600 effects, progress track 4dp with a 4dp stop. Anything marked “not in M3” is my design decision.
